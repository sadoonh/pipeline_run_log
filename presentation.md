**NEWT + Databricks Genie:** Start on the left: the user asks a question in NEWT, and the NEWT backend sends it directly to Genie. Genie uses our Unity Catalog metric views to understand the business rules and how metrics are calculated, which dimensions to group by, and how tables relate. It generates a query, and the Databricks SQL warehouse runs that query against the metric views over our migrated tables. The results go back to Genie, and NEWT displays the plain-language answer. In this path, we define the business rules in metric views, while Genie manages the question-to-answer workflow.

**NEWT + NeeAI:** Again, the user starts by asking a question in NEWT. This time, the NEWT backend loads the relevant business definitions from our YAML file and sends them with the question to NeeAI. NeeAI returns SQL, but it does not run it: NEWT validates the SQL and executes it against RDS using its existing connection. NEWT then sends the question and query results to NeeAI for a plain-language explanation, which NEWT displays to the user. In this path, NeeAI generates SQL and explains results, while we build the workflow in NEWT and keep control of database execution.
